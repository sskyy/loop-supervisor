我们在全局有生成任务的 skill，它们能自动启动新 session，用主从编排或循环的方式解决问题。每个任务一次只处理一个问题；本文按`依赖`列与`并发上限`同时运行多个互不依赖的任务，`隔离`=`worktree` 的任务各在自己的 worktree 与分支上运行，完成时由任务自己合入 `{{主分支}}`。队列项分三类：`编排`项派发一个主从编排任务（新 session 生成任务文件并作为主 agent 运行到终态，终态后接力回本文）；`循环`项派发单个循环任务；`并列`项派发一个并行批次（由新 session 建立并行监督，汇合完成后接力回本文）。

你的任务是：检查一次本文「队列」表，并按下面的分支执行。处理完即结束，不要向用户提问。

你只做队列调度、改本文「队列」表中的状态、按「建立 worktree」与「收尾 worktree」执行 git 命令、按第 0 步同步本文的改动、按模板启动新 session。不要自己调用任务生成 skill，不要自己当主 agent，不要自己建立并行监督或执行汇合，不要自己执行 Task 1，不要自己修复代码。不要修改来源文档。不要改写队列项的范围或正文。

## 分支

0. {{拉取}}读本文「队列」表。本文的每次改动在标记后立即同步。下文的「同步」指：{{同步}}

1. 如果本文开头 status 为`已解除`或`已完成`，直接结束，不启动新 session。

2. 如果全部任务都已经结束（没有`未修复`也没有`修复中`）：将本文开头 status 改为`已完成`，直接结束。

3. 对每一个`修复中`的任务，按该行`类型`检查进度：`编排`项与`循环`项读任务方案文档 `<执行目录>/docs/${任务名}/${任务名}.md`，按 3.1–3.3 执行；`并列`项读并列文档 `prompt/${任务名}.md`，按 3.4–3.6 执行。`执行目录`由该行`隔离`列决定：`main` 为主仓库根，`worktree` 为 `{{hub}}/${任务名}`。

   3.1. 如果 status 为`已完成`：`隔离`=`worktree` 时先按「收尾 worktree」执行；收尾成立后（或`隔离`=`main`）将该行状态改为`已修复`，同步。收尾不成立时该行保持`修复中`，在结束前报告。

   3.2. 如果 status 为`停止尝试`、`不可实现`或`协议失败`：将该行状态改为`已终止`，同步。worktree 与分支保留给用户，本文不处理。

   3.3. 如果没有该文件，或 status 为`立项中`或`实现中`：该行不动。

   3.4. 如果 status 为`已完成`：将该行状态改为`已修复`，同步。

   3.5. 如果 status 为`部分完成`或`已解除`：将该行状态改为`已终止`，同步。汇合残留的 worktree 与分支保留给用户，本文不处理。

   3.6. 如果没有该文件，或 status 为`进行中`或`汇合中`：该行不动。

4. 当`修复中`的行数少于`并发上限`时派发：按优先级（相同则取表中更靠前的一行）选取一个`未修复`、且`依赖`列中每个 id 的状态都为`已修复`（`依赖`为`无`视为满足）的任务；`隔离`=`main` 的行只在没有其它`隔离`=`main` 的`修复中`行时可派发；先把该行状态改为`修复中`并同步；`隔离`=`worktree` 时按「建立 worktree」执行；再按该行`类型`选模板作为 prompt：`编排`用「编排派发模板」，`循环`用「循环派发模板」，`并列`用「并列派发模板」。把模板中的`${任务名}`换成该行的任务名、`${范围}`换成该行范围的原文、`${执行目录}`换成该行的执行目录；`隔离`=`worktree` 的`编排`项保留模板第 6 条，其它情况删去第 6 条。用「会话启动」中的方法启动新 session，启动参数为「会话启动参数」中的参数并把 `-w` 改为该行的执行目录，prompt 为填好的模板。重复本步直到`修复中`的行数达到`并发上限`或没有可派发的任务。`依赖`中含`已终止`任务的行不可派发，在结束前报告。

5. 结束前报告：本轮改动的行、启动的 session、因依赖未满足或收尾不成立而未处理的行。本轮没有任何改动时只报告一句。

## 建立 worktree

在主仓库根执行；`git status --porcelain` 非空时先 `git add -A && git commit -m "queue: 派发前提交" && git push {{远端}} {{主分支}}`。

```bash
git worktree add -b ${任务名} {{hub}}/${任务名} {{主分支}}
{{WORKTREE_SETUP}}
```

## 收尾 worktree

在主仓库根执行。成立条件：`git fetch {{远端}} && git merge-base --is-ancestor ${任务名} {{远端}}/{{主分支}}` 退出 0（任务的分支已合入 `{{主分支}}`）。成立时（远端分支已不存在时跳过最后一条）：

```bash
git worktree remove {{hub}}/${任务名}
git branch -d ${任务名}
git push {{远端}} --delete ${任务名}
```

不成立时不执行任何删除，该行保持`修复中`。
