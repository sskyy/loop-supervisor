我们在全局有生成任务的 skill，它们能自动启动新 session，用主从编排或循环的方式解决问题。但是它们一次只能处理一个问题。队列项分三类：`编排`项派发一个主从编排任务（新 session 生成任务文件并作为主 agent 运行到终态，终态后接力回本文）；`循环`项派发单个循环任务；`并列`项派发一个并行批次（由新 session 建立并行监督，汇合完成后接力回本文）。

你的任务是：检查一次本文「队列」表，并按下面的分支执行。处理完即结束，不要向用户提问。

你只做队列调度、改本文「队列」表中的状态、在完成时提交改动、按模板启动新 session。不要自己调用任务生成 skill，不要自己当主 agent，不要自己建立并行监督或执行汇合，不要自己执行 Task 1，不要自己修复代码。不要修改来源文档。不要改写队列项的范围或正文。

## 分支

1. 如果本文开头 status 为`已解除`或`已完成`，直接结束，不启动新 session。

2. 如果全部任务都已经结束（没有`未修复`也没有`修复中`）：将本文开头 status 改为`已完成`，直接结束。

3. 如果没有任何`修复中`的任务，就选取优先级最高的一个`未修复`任务（优先级相同则取表中更靠前的一行），先把该行状态改为`修复中`，再按该行`类型`选模板作为 prompt：`编排`用「编排派发模板」，`循环`用「循环派发模板」，`并列`用「并列派发模板」。把模板中的`${任务名}`换成该行的任务名，把其中的`${范围}`换成该行的范围原文。使用 `{{SESSION_SKILL}}` 中的方法启动一个新的 chat，prompt 为填好的模板，启动参数 `{{会话启动参数}}`（本地后端的新建会话命令不接受路径，不写 `-w` 时新会话落在当前前台 workspace）。特别注意：替换后的任务名和范围必须与选中行完全一致。不要自己执行模板。只要启动就可以结束，不需要等待。

4. 如果有`修复中`的任务，按该行`类型`检查进度：`编排`项与`循环`项读任务方案文档 `docs/${任务名}/${任务名}.md`，按 4.1–4.3 执行；`并列`项读并列文档 `prompt/${任务名}.md`，按 4.4–4.6 执行。

   4.1. 如果 status 为`已完成`：按以下顺序执行：1. 先提交所有改动，将「队列」表中该行状态改为`已修复`。2. 按第 3 步选取下一个`未修复`任务。若没有`未修复`任务，将本文开头 status 改为`已完成`，然后结束。

   4.2. 如果 status 为`停止尝试`、`不可实现`或`协议失败`：提交所有改动，将「队列」表中该行状态改为`已终止`，然后按第 3 步选取下一个`未修复`任务。

   4.3. 如果没有该文件，或 status 为`立项中`或`实现中`：直接结束，不启动新 session。任务尚未终止；若这是误启动，等任务自己在终态时再执行本文。

   4.4. 如果 status 为`已完成`：按以下顺序执行：1. 先提交所有改动，将「队列」表中该行状态改为`已修复`。2. 按第 3 步选取下一个`未修复`任务。若没有`未修复`任务，将本文开头 status 改为`已完成`，然后结束。

   4.5. 如果 status 为`部分完成`或`已解除`：提交所有改动，将「队列」表中该行状态改为`已终止`，然后按第 3 步选取下一个`未修复`任务。汇合残留的 worktree 与分支保留给用户，本文不处理。

   4.6. 如果没有该文件，或 status 为`进行中`或`汇合中`：直接结束，不启动新 session。并行批次尚未终止；若这是误启动，等批次汇合完成时再执行本文。

## 编排派发模板

```
生成主从编排任务并执行：
使用全局 skill orchestrated-task 生成任务文件，然后在本 session 里作为主 agent 执行它。需求：${范围}，以其中描述的事项为任务需求。{{自有框架条款}}

注意：
1. 一定使用 ${任务名} 作为任务 slug（任务文件 docs/${任务名}/${任务名}-task.md）。范围中的「本文」指队列文档 `{{队列文档}}`。
2. 模型放置：{{模型放置}}。
3. 本任务属于队列 `{{队列文档}}`。生成任务文件时，在「任务」一节的「任务特定说明」里写入下面这段接力条款（原文），并在 retro.md 的运行标题之后重复一次：「本任务属于队列 `{{队列文档}}`。主 agent 在任何终止出口（状态头 status 为 已完成、停止尝试、不可实现 或 协议失败）向用户报告之后，使用 `{{SESSION_SKILL}}` 中的方法启动一个新的 chat，prompt 为 `Please execute {{队列文档}}`，启动参数 `-w {{主仓库根}}`，只要启动就可以结束，不要自己执行队列文档。主会话中断后恢复的主 agent 到终态时同样执行本条。」
4. 生成后不要停下等待用户：立即按任务文件「主 agent」段的「首次进入」开始立项，并全程作为主 agent 运行到终态，终态后按第 3 条接力。若 docs/${任务名}/${任务名}-task.md 已经存在（上一个主会话中断），不要重新生成，按「主会话中断后的恢复」继续。
5. 生成阶段无法完成（准入分类或价值判断写不出、前置资源不满足等需要用户决定的情况）时不要向用户提问：把原因写进 docs/${任务名}/retro.md（目录不存在则创建；不要写任务文件和方案文档），到队列文档「队列」表中把任务名为 ${任务名} 的一行状态改为`已终止`，提交改动，然后用第 3 条的方法启动 `Please execute {{队列文档}}`，启动即结束。重新派发时沿用同一 slug 与目录（只留下 retro.md、没有任务文件的目录不算已有任务），不改用 -v2 等新 slug。
```
