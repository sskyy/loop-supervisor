# 任务

status: 进行中

会话后端：{{会话后端}}
会话启动：`{{SESSION_SKILL}}`
主仓库根：`{{主仓库根}}`

我们在全局有一个生成循环任务的 skill，它能自动启动新 session，用循环的方式解决问题。但是它一次只能处理一个问题。队列项分两类：`循环`项派发单个循环任务；`并列`项派发一个并行批次（由新 session 建立并行监督，汇合完成后接力回本文）。

你的任务是：检查一次本文「队列」表，并按下面的分支执行。处理完即结束，不要向用户提问。

你只做队列调度、改本文「队列」表中的状态、在完成时提交改动、按模板启动新 session。不要自己调用循环任务生成 skill，不要自己建立并行监督或执行汇合，不要自己执行 Task 1，不要自己修复代码。不要修改来源文档。不要改写队列项的范围或正文。

## 分支

1. 如果本文开头 status 为`已解除`或`已完成`，直接结束，不启动新 session。

2. 如果全部任务都已经结束（没有`未修复`也没有`修复中`）：将本文开头 status 改为`已完成`，直接结束。

3. 如果没有任何`修复中`的任务，就选取优先级最高的一个`未修复`任务（优先级相同则取表中更靠前的一行），先把该行状态改为`修复中`，再按该行`类型`选模板作为 prompt：`循环`用「任务模板」，`并列`用「并列派发模板」。把模板中的`${任务名}`换成该行的任务名，把其中的`${范围}`换成该行的范围原文。使用 `{{SESSION_SKILL}}` 中的方法启动一个新的 chat，prompt 为填好的模板，启动参数 `-w {{主仓库根}}`（本地后端的新建会话命令不接受路径，不写 `-w` 时新会话落在当前前台 workspace）。特别注意：替换后的任务名和范围必须与选中行完全一致。不要自己执行模板。只要启动就可以结束，不需要等待。

4. 如果有`修复中`的任务，按该行`类型`检查进度：`循环`项读任务方案文档 `docs/${任务名}/${任务名}.md`，按 4.1–4.3 执行；`并列`项读并列文档 `prompt/${任务名}.md`，按 4.4–4.6 执行。

   4.1. 如果 status 为已完成，并且没有 next-action 了，说明真的完成了。按以下顺序执行：1. 先提交所有改动，将「队列」表中该行状态改为`已修复`。2. 按第 3 步选取下一个`未修复`任务。若没有`未修复`任务，将本文开头 status 改为`已完成`，然后结束。

   4.2. 如果 status 为不可实现或协议失败：提交所有改动，将「队列」表中该行状态改为`已终止`，然后按第 3 步选取下一个`未修复`任务。

   4.3. 如果没有该文件，或 status 仍为设计中或实现中：直接结束，不启动新 session。循环任务尚未终止；若这是误启动，等待循环自己在终止时再执行本文。

   4.4. 如果 status 为`已完成`：按以下顺序执行：1. 先提交所有改动，将「队列」表中该行状态改为`已修复`。2. 按第 3 步选取下一个`未修复`任务。若没有`未修复`任务，将本文开头 status 改为`已完成`，然后结束。

   4.5. 如果 status 为`部分完成`或`已解除`：提交所有改动，将「队列」表中该行状态改为`已终止`，然后按第 3 步选取下一个`未修复`任务。汇合残留的 worktree 与分支保留给用户，本文不处理。

   4.6. 如果没有该文件，或 status 为`进行中`或`汇合中`：直接结束，不启动新 session。并行批次尚未终止；若这是误启动，等批次汇合完成时再执行本文。

## 任务模板

```
生成循环任务：
${范围}，深度求证其中指出的所有问题，如果问题存在就进行修复。{{自有框架条款}}

注意：
1. 一定使用 ${任务名} 作为任务名.
2. 启动新 session 的部分使用 {{会话后端}} 的版本.
3. 如果正常生成任务，完成后应该直接启动新 session 执行 Task 1.
4. 本循环任务属于队列 `{{队列文档}}`。生成任务文件时必须把该路径写入任务文件头部 `queue:` 字段，并把所有终止出口写成启动 `Please execute {{队列文档}}`（不要写成「终止，不启动新的 chat」）。
```

```
注意：
1. 一定使用 ${任务名} 作为监督名，并列文档为 prompt/${任务名}.md。范围中的「本文」指队列文档 `{{队列文档}}`。
2. 本批次属于队列 `{{队列文档}}`：建立时必须把 `queue: {{队列文档}}` 写入并列文档头部，汇合终止句写成启动 `Please execute {{队列文档}}`；队列接力使用 {{会话后端}} 的版本，启动参数 `-w {{主仓库根}}`。
3. 全部扇出即完成，不要等待，不要自己执行 Task 1，也不要自己执行「分支」或「汇合」一节。
4. {{并列条款注意}}
```
